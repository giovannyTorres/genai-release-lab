# Trust model and limitations

All included data is synthetic. No employer documents, real accounts or production transactions are involved. No regulatory certification is asserted.

The server is the authorization boundary. Viewer cannot create datasets/configurations/jobs; operator cannot approve releases; reviewer cannot change dataset contents. Approval requires a completed approved gate and records input/results hashes. Human review is append-only and cannot override missing mandatory evaluations. CSRF protections use strict cookies and origin/fetch-site validation; imports have bounded bodies and strict unique case identifiers. Session tokens are random, stored as hashes scoped to the active mode and expire after eight hours. LIVE password hashes use salted scrypt; a managed identity provider, login throttling and account lifecycle are future production integrations.

Imported output and context are untrusted. HTML exports escape all text and carry a restrictive CSP. SDK errors are sanitized. The LLM judge receives untrusted-data instructions and validated structured schemas, but this is not a guarantee against prompt injection. Deterministic authorization tests establish application checks, not model immunity. Imported backend_trace markers are assertions by the trusted importer and require authentic external provenance in production.

Endpoint operators can register only exact environment-allowlisted HTTPS hosts. The worker rejects non-global DNS results and pins the public IP to prevent a subsequent DNS rebind, while preserving TLS hostname validation. No automatic redirect follows. This restricts SSRF; endpoint business authorization remains the endpoint owner's responsibility.

Do not commit `.env`, API keys, credential JSON or local databases. Use backend environment injection / secret stores. Rotate compromised keys, revoke affected sessions by deleting session rows, inspect audit by correlation ID, and rerun affected evaluations under a new configuration version. Database DEMO passwords in Compose are intentionally public local-only defaults. Change database credentials and TLS settings before any external exposure.

Known boundaries: single shared workspace organization (role authorization, not a multi-tenant product); no OIDC provider, email notifications, endpoint bearer-secret management, semantic proof of factual correctness or model benchmark claims. Deterministic fact checks are explicit fixture assertions. Final cases are tagged and reported separately but visible to authorized reviewers; this is not a confidential benchmark service. Job results are bounded to1000 cases per import; case/job listings do not yet paginate. Cancellation waits for the active bounded request to return. Workers persist progress and fence stale writes; provider calls may repeat if a worker dies before saving an output, so providers/endpoints should tolerate read-only evaluation retries.
